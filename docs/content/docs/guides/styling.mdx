title: Styling and theming
description: Theme groups with six CSS custom properties, add your own class names, and get dark mode, forced colors and print right.
---

The bundled stylesheet is deliberately plain. It handles layout and states and leaves fonts, spacing and colors to your site. Most theming needs only custom properties.

## Custom properties

Set these on `.rehype-code-group`, or on any ancestor of it.

| Property                      | Default (light / dark)    | Used for                                           |
| ----------------------------- | ------------------------- | -------------------------------------------------- |
| `--rcg-accent`                | `#2563eb` / `#60a5fa`     | The underline on the active tab.                   |
| `--rcg-border-color`          | `#d4d4d8` / `#3f3f46`     | The line between the tabs and the panels.          |
| `--rcg-focus-color`           | `#2563eb` / `#93c5fd`     | The keyboard focus outline.                        |
| `--rcg-tab-background`        | `transparent`             | Inactive tab background.                           |
| `--rcg-tab-background-active` | `#f4f4f5` / `#27272a`     | Active tab background.                             |
| `--rcg-tab-color`             | `inherit`                 | Tab text color.                                    |

```css
.rehype-code-group {
  --rcg-accent: rebeccapurple;
  --rcg-focus-color: rebeccapurple;
  --rcg-tab-background-active: color-mix(in srgb, rebeccapurple 12%, transparent);
}
```

## Dark mode

The defaults are written with `light-dark()`, so they follow the CSS `color-scheme` of the page. Browsers without `light-dark()` fall back to the `prefers-color-scheme` media query.

That works when your theme switch sets `color-scheme`, as most theme libraries do. If your dark mode is only a class, set the properties under that class instead. This site maps them to its own palette, so tabs always match the theme toggle:

```css title="app/global.css"
.rehype-code-group {
  --rcg-accent: var(--color-fd-primary);
  --rcg-border-color: var(--color-fd-border);
  --rcg-focus-color: var(--color-fd-ring);
  --rcg-tab-background: transparent;
  --rcg-tab-background-active: var(--color-fd-card);
  --rcg-tab-color: var(--color-fd-muted-foreground);
}
```

## Class names

Every group uses the same small set of classes:

| Element                | Default class         | `customClassNames` key  |
| ---------------------- | --------------------- | ----------------------- |
| The group              | `rehype-code-group`   | `codeGroupClass`        |
| The tab list           | `rcg-tab-container`   | `tabContainerClass`     |
| Each tab button        | `rcg-tab`             | `tabClass`              |
| Each panel             | `rcg-block`           | `blockContainerClass`   |
| The selected tab       | `active`              | `activeTabClass`        |
| The selected panel     | `active`              | `activeBlockClass`      |

[`customClassNames`](/docs/reference/options#customclassnames) **adds** your classes next to the defaults instead of replacing them. The client and the bundled stylesheet rely on the default classes, so they keep working. This is handy for utility-class frameworks:

```js
unified().use(rehypeCodeGroup, {
  customClassNames: {
    codeGroupClass: "not-prose my-6 rounded-xl border",
    tabClass: "px-3 py-2 text-sm",
    activeTabClass: "text-orange-600",
  },
});
```

Space-separated values become several classes. Custom active classes are stored on the group, as `data-rcg-active-tab-classes` and `data-rcg-active-block-classes`, so the client can move them when the selection changes.

## Styling states

Besides the `active` classes, you can style from attributes that are always accurate:

```css
/* The selected tab */
.rcg-tab[aria-selected="true"] {
  font-weight: 600;
}

/* Only after the client has set the group up */
.rehype-code-group[data-rcg-enhanced] {
  border: 1px solid var(--rcg-border-color);
}

/* Vertical groups */
.rehype-code-group[data-rcg-orientation="vertical"] {
  gap: 1rem;
}
```

## Built-in behavior worth knowing

- **Before the client runs**, every panel is visible. Panels are hidden only inside `[data-rcg-enhanced]` groups, so readers without JavaScript see all the content.
- **Long code scrolls** inside its panel instead of widening the page, and a long row of tabs scrolls sideways.
- **Forced colors** (Windows high contrast): the accent, border and focus colors switch to system colors.
- **Print:** the tab list is hidden, every panel is printed, and each one is headed by its label.
- **Vertical groups** use a two-column grid: tabs on the start side, panels next to them.

## Without the bundled stylesheet

You can skip `styles.css` and write all the CSS yourself. The client doesn't depend on it, but it does set the `hidden` attribute on inactive panels, so make sure your CSS doesn't override `[hidden]` with a `display` value. To show all panels until the client has run, hide panels only inside `[data-rcg-enhanced]`, as the bundled stylesheet does.
